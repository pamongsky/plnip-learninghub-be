# Checklist Latihan Presentasi - 3 Skenario Audiens

Target sesi: `30 menit presentasi + 10 menit Q&A`.

## Skenario 1 - Campuran HCIS/HCD + ITD (Skenario Utama)
### Fokus
- 70% dampak operasional.
- 30% arsitektur teknis ringkas.

### Checklist sebelum latihan
- [ ] Slide 1-4 menegaskan masalah bisnis dan value dalam <= 10 menit pertama.
- [ ] Istilah teknis dijelaskan dengan bahasa non-jargon.
- [ ] Metrik disamarkan dan konsisten di seluruh slide.

### Checklist saat latihan
- [ ] Total paparan selesai <= 30 menit.
- [ ] Sisakan >= 8 menit untuk Q&A.
- [ ] Demo selesai <= 7 menit.

### Evaluasi pasca latihan
- [ ] Apakah audiens non-teknis paham "so what" tiap bagian?
- [ ] Apakah transisi ke appendix mulus saat ada pertanyaan teknis?

## Skenario 2 - Dominan HCIS/HCD (Bisnis Operasional)
### Fokus
- 80% proses, dampak, KPI, roadmap implementasi.
- 20% teknis secukupnya.

### Penyesuaian delivery
- [ ] Percepat Slide 5 teknis menjadi <= 2 menit.
- [ ] Perkuat Slide 8, 9, 11, 14, 18 (dampak operasional).
- [ ] Gunakan contoh proses kerja harian, bukan istilah framework.

### Red flag yang harus dihindari
- [ ] Jangan terlalu lama di detail endpoint/controller.
- [ ] Jangan membuka issue teknis terlalu dalam di deck utama.

## Skenario 3 - Dominan ITD (Teknis)
### Fokus
- 50% nilai + 50% detail implementasi.

### Penyesuaian delivery
- [ ] Deck utama tetap 30 menit, tapi siapkan appendix aktif.
- [ ] Siapkan penjelasan A1-A10 terstruktur untuk Q&A.
- [ ] Siapkan trade-off dan risiko serta mitigasi prioritas.

### Pertanyaan yang wajib siap
- [ ] Authz consistency strategy.
- [ ] Integrasi Moodle/ERP failure handling.
- [ ] Test strategy dan release hardening plan.

## Uji Validasi Materi (Pass/Fail)
### 1) Timebox test
- [ ] Pass jika paparan <= 30 menit dan Q&A tersisa >= 8 menit.

### 2) Audience clarity test (HCIS/HCD)
- [ ] Pass jika value bisnis sudah jelas sebelum menit ke-10.

### 3) Technical depth test (ITD)
- [ ] Pass jika pertanyaan teknis terjawab via appendix tanpa mengubah struktur deck utama.

### 4) Demo reliability test
- [ ] Pass jika demo utama selesai <= 7 menit.
- [ ] Pass jika fallback A/B/C dapat dijalankan tanpa jeda panjang.

### 5) Confidentiality test
- [ ] Pass jika tidak ada token, password, URL internal sensitif, atau data personal mentah.

### 6) Consistency test
- [ ] Pass jika angka dan narasi konsisten di deck, demo script, dan Q&A.

### 7) Story coherence test
- [ ] Pass jika tiap slide menjawab pertanyaan "so what" untuk PLN IP.

## Runbook Gladi Bersih (H-1)
- [ ] Latihan full 1x (real timing).
- [ ] Latihan Q&A 20 menit dengan 10 pertanyaan random.
- [ ] Uji demo + fallback sekali.
- [ ] Finalisasi opening dan closing statement.
